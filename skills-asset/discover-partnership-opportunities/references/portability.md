# 跨系统可移植执行

本 Skill 不依赖特定浏览器、搜索引擎、文件根目录或内部系统。迁移时至少复制 `SKILL.md`、`references/`、`assets/` 和 `scripts/`，保持相对路径不变。`agents/openai.yaml` 属于 Codex UI 元数据；迁移到 Claude Code 等其他系统时可以省略，避免把来源系统专属配置带入目标系统。

## 能力适配顺序

### 联网检索

1. 优先使用目标环境提供的浏览器、搜索或网页读取工具；
2. 中国公司可组合国家企业信用信息公示、地方市场监管、政府采购/公共资源、工信备案、裁判文书、企业官网、公众号、招聘与代码生态等来源；
3. 无联网能力时，只基于用户提供材料工作，显著注明未实时核验，不伪造URL或当前状态。

### 本地资料

使用环境原生文件读取能力。先建立文件清单，再按主体、客户项目、产品技术、合作口碑、我方能力分类读取。不得修改原始证据文件。

### 输出转换

- 能生成HTML：从Markdown转换为自包含HTML并做视觉检查；
- 只能输出文本：交付Markdown与CSV；
- 能生成演示稿/文档：以主报告为唯一事实源，避免多个版本结论漂移。

### 并行研究

环境允许且用户授权时，可按“主体资本、客户项目、产品技术与口碑、商业机会”并行。主执行者必须统一实体、证据标签、截止日期和机会阶段，不能直接拼接互相矛盾的结论。

## 零依赖原则

- `scripts/score_opportunities.py` 仅使用 Python 标准库；没有 Python 时按同一权重人工计算。
- 路径全部使用 Skill 内相对路径；报告中的客户资料路径由运行环境决定。
- 不硬编码账号、Cookie、API密钥、公司名称或私有系统地址。
- 环境缺少某种工具时降级输出，不把工具缺失误判为业务事实缺失。

## 移植验收

在新系统中完成四项检查：

1. 能读取 `SKILL.md` 及五个引用文档；
2. 能复制并填写三个 `assets/` 模板；
3. 能运行评分脚本的 `--self-test`，或人工复核同一示例结果；
4. 用一个未出现在本 Skill 中的混合型公司做前向测试，确认输出会随经营模式变化，而不是复刻固定模板。
