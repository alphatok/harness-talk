# 客户提案包｜演示稿、问答与方案

把已确认的客户需求和我方能力，整理成可复用的客户报告、演示稿、问答手册及技术方案。只生成本次需要的材料，不默认全套输出。

## 输入

优先复用当前对话或用户指定的客户研究与会议报告。可接收 client-intel、client-meeting-intel 的产物，也可直接使用信息卡，不强制安装其他技能。

按任务核对客户名称、沟通阶段、客户目标与需求、我方已验证能力、用户范围、技术环境、试点重点和交付对象。已有信息不重复问。缺口不阻止已有材料的整理，影响承诺和方案范围的内容写待确认。

## 产物选择

| 用户用途 | 模板 |
|---|---|
| 客户研究存档 | templates/report.md |
| A4 阅读报告 | templates/report-a4.html |
| 提案或演示 | templates/deck-13p.html |
| 会前问答准备 | templates/qa-handbook.html |
| 管理层方案 | templates/tech-solution-mgmt.html |
| 技术评审方案 | templates/tech-solution-dev.html |

只读选用模板。13 页是演示模板起点，按内容增减。演示稿默认 HTML，不宣称已生成 PPTX。内部问答手册和客户外发方案的语气、范围要区分。

## 生成流程

1. 建立事实底稿：客户事实、我方事实、建议、假设和待确认项分开，并保留来源。
2. 确定本次沟通的目标，按现状、需求、范围、方案、验证方式和下一步展开，按用户指定结构裁剪。
3. 复制选用模板到用户指定目录，填入事实和建议。模板中的示例不能当成已实现功能或客户承诺。
4. 报价、日期、SLA、收益和验收阈值只有来源明确时才能写成承诺；建议参数标明需双方确认，试点结果尚未测量则保留未验证。
5. 核对各份材料的术语、数字、范围和里程碑一致，旧版本保留，不覆盖用户原稿。

## 模板与内容边界

保留模板可用的导航、版式及打印能力。允许按本次用途调整设计，不宣称未经测量的配色或布局已通过认证。全部 CSS/JS 优先内联，无外部资源时才称为离线可用。

客户版保留必要依据、假设和限制，可用脚注表达。技术开发版按需保留代码或接口说明；不能为美观删掉影响执行的信息。缺少来源时列待确认，不伪装已核实。

分享包不带真实客户笔记。不得从作者机器补找客户档案。用户明确要求知识收录时，仅在指定知识库范围保存经过确认的内容，不自动回填技能目录。

## 检查与交付

检查占位符、来源、数字、文件名和页面结构。实际打开 HTML 检查桌面与移动布局、导航和打印；未执行的视觉或运行检查如实说明。静态检查不能证明已完成客户验收。

交付文件路径、核心结论和待确认项。文件交付不自动发送、发布或承诺商务条款。

## 试用

- 根据需求确认表，生成一份客户提案 HTML，范围和待确认项分开。
- 把客户研究和会议纪要整理成演示稿、问答手册和管理层方案。
- 更新技术评审版，保留接口细节，对照上一版列出范围变化。

教学示例：客户要求验证三类文档检索，应写为试点范围。没有测试记录时，不能写成三类文档已经全部验收通过。
