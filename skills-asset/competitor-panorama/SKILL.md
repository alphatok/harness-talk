# 竞品全景图｜业务架构与能力拆解

基于官方公开资料，串联业务架构、产品分层与模块能力，交付可追溯的竞品全景 HTML。适合 ToB、SaaS 和平台产品的产品规划、售前与战略研究。

## 开始工作

识别目标公司、产品范围、分析日期和交付对象。用户提供参考报告时借鉴结构，不假定作者本机有样本。关键范围不清才追问。先简要说明计划并继续；只有用户要求先审计划时等待确认。

## 分析方法

1. 按 [采集方法](references/methodology.md) 列业务链和待回答的问题。
2. 按 [官方来源](references/source-whitelist.md) 确认目标公司的官网、帮助中心、开发文档、财报和公告。仅把有直接依据的能力纳入事实层。
3. 为每条事实记录来源、访问日、适用版本或地区和证据状态。官方宣传标为厂商声明，不能当成独立实测。
4. 对齐名称、指标与披露口径。来源冲突记录原因，未确认能力、价格或发布状态明确列出，不把搜索不到解释成不存在。
5. 合成三段：业务怎么运转、产品怎样承载、各模块有什么能力。按 [报告结构](references/report-spec.md) 生成本地 HTML。

## 核心模块与表达

核心模块可用星号标注，依据是缺少该模块将中断已定义的主要业务链。逐项说明原因，不按比例凑数。未覆盖的业务链与未知能力要保留边界。

不能把营销产品清单直接当成架构。图中箭头注明数据、调用、顺序或业务关系；没有因果证据不画成确定因果。厂商之间只有在范围、时间和计量单位一致时才比较。

## 验证与交付

按 [检查清单](references/qa-checklist.md) 核对来源、计数、锚点、配色和布局。随包 scripts/svg-overflow-qa.js 可在 Node.js 与 Chromium 可用时辅助检查 SVG 文字越界；脚本路径相对于本技能目录，浏览器路径由当前环境确定。

实际打开报告检查主题切换、导航、窄屏、文字和图形。脚本通过不代表视觉无碰撞，更不能证明厂商功能已经实测。缺少运行环境时如实说明检查范围。

默认串行完成；只有用户授权并行代理工作时才分派，保持证据口径一致。不固定依赖其他技能或作者机器环境。文件保存遵循用户指定目录。

## 试用

- 分析某家 SaaS 的业务和产品全景，附模块能力地图，每项附官方来源。
- 按这份参考报告的结构研究另一家公司，未确认能力单独列出。
- 更新旧竞品报告，标明改名、发布状态和指标口径变化。

教学示例：官网写“支持客户标签”，可列该能力并附来源；不能补写未公开的接口性能、成交价格和上线效果。
