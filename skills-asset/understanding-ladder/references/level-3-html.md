# 交互解释页

适用于参数影响、边界行为和方案取舍。交互展示模型的结果，不自动构成模型正确或现实成立的证据。

## 设计

1. 明确结论或学习目标、公式、假设和参数口径。
2. 选择少量关键参数；通常1至3个即可，数量以读者任务为准。
3. 给参数合理范围、默认值和单位。区分教学设置与真实业务取值。
4. 默认状态先能读懂，再引导“预测—操作—观察—解释”。不要求读者先猜才能看到答案。
5. 提供一个能暴露误解的边界例子，并说明模型失效范围。

推荐组织：结论或目标、交互区域、机制说明、必要的尝试提示和模型边界。按内容调整，不强制固定区块。

## 实现

优先单文件 HTML，内联 CSS/JS，使用 SVG 或 Canvas，避免不必要的构建与外部依赖。确需依赖时说明联网或运行条件，不把依赖网络的页面宣称为离线可用。

- 参数、坐标轴和结果写明名称与单位；无量纲量明确其含义。
- 控件支持键盘操作，提供标签；触屏可操作，颜色另配文字或线型。
- 参数变化时更新计算、图形和说明，不只移动装饰元素。
- 条件切换、无效输入或超出模型定义域时提供明确状态，不展示无意义数值。
- 提供重置或重现当前设置的方法，以便核对结果。

## 验证与交付

对默认值、至少一个可手算值和相关边界值核对模型输出。实际打开页面，操作控件，检查计算、标签、布局及控制台错误。若未能运行，只能报告静态检查及原因。

保存位置遵循任务的文件约定。交付链接，简短说明先操作什么及主要限制。不得用浏览器打开成功代替公式验证或读者验收。
