# 客户会后推进｜需求、证据、下一步

从纪要中找出客户关心什么、哪些已经确认、下一步还缺什么。先给可行动的结论，再保留可追溯证据。

## 输入与模式

接收粘贴纪要、逐字稿或用户指定的文本、图片和文件。只读本次选定材料，不搜索作者历史客户资料。没有材料时请用户提供，不能根据会议名称猜内容。

默认给简明分析和跟进清单。用户要正式报告或文件时，使用模板生成两份自包含 HTML。日期、参会人或角色缺失时写待确认，先分析已知部分。

图片优先用宿主图像能力读取。macOS 可选运行随包 scripts/ocr.swift，路径相对于本技能目录；其他环境使用可用 OCR。无法识别时说明缺口，OCR 结果需核对。不具备转写能力时不声称已听取录音。

## 分析方法

1. 建立来源清单。总结用于导航，逐字稿和原始材料用于核对；冲突保留，不静默裁决。
2. 按 [分析框架](references/frameworks.md) 查找痛点、认可、需求、方向、决策、竞争和合作关系。没有证据写本次未捕捉到，不硬凑。
3. 证据记录原文或明确标识的转述、来源位置、说话人及角色、时间或承诺状态。未知字段写待确认。编号片段不能证明说话人身份。
4. 分开事实、推断和建议。客户明确需求与我方建议分开；没有基线和测量记录时，不编造损失、收益或情绪分数。
5. 给优先级及依据。已确认期限和决策优先于分析者评分；信息不足不强行排序。
6. 跟进行动说明做什么、为何做、谁确认、输入和完成标志。负责人、时限无来源时标为建议或待确认。

沉默、未提竞品或暂未回复，不能单独证明意愿、信任和内部关系。预算及权限以明确证据和后续确认为准。

## 正式报告

读取 [HTML 规范](references/html-design.md)，按需求选模板：

- templates/report-analysis.html：背景、证据、需求、优先级和风险。
- templates/report-strategy.html：追问、阶段行动、协作条件和备选安排。
- templates/canvas-blank.html：仅在用户需要空白工作表时使用。

保留导航、主题切换、折叠和打印机制。模板示意文字及数字须替换，缺失内容明确写待确认。可删减空洞内容，不为填模板编造。保留来源和内部使用声明。

生成后检查占位符、来源、锚点和内容一致性。能打开浏览器时，实际核对桌面与移动布局、主题和折叠；未做的检查如实说明。

对比多场会议时，只读用户指定旧报告，列新增、变化、冲突和未解决项，保留旧版本。未要求知识收录时，不把客户原话、身份和会议记录写入技能包或长期知识库。

有配套技能时，可复用 client-intel 的已核实事实，或把需求交给 client-deliverables；不依赖配套技能才能工作。

## 试用

- 分析这份纪要，列明确需求、推断、待确认项和下一步。
- 做两份离线 HTML：会议分析报告和跟进清单。
- 对照上次报告，哪些诉求、期限和决策条件变了？

教学示例：“希望月底前看到演示，但预算还没定。”应拆为期望月底演示、预算未确认，不能写成已立项或已承诺购买。
