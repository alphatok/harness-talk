# 客户会议分析框架

## 证据记录

每条重要信息记录原文或明确标识的转述、说话人及角色、文件位置或时间戳、时间或承诺状态。未知字段写待确认。不要把转写编号当成身份，也不要虚构原话。

## 七类信号

| 类别 | 查找什么 | 易错边界 |
|---|---|---|
| 痛点 | 当前困难、频率、影响和期望落差 | 后果推演是推断，不能编造损失 |
| 认可 | 明确肯定、继续使用的理由 | 表扬不等于采购承诺 |
| 需求 | 明确要求、困境暗示的可能需求 | 我方建议与客户要求分开 |
| 方向 | 目标、时间和计划 | 愿景不等于已排期 |
| 决策 | 预算、审批、评估标准与参与人 | 职位不等于拍板权 |
| 竞争 | 客户明确提及的替代方案 | 未提竞品不证明没有竞争 |
| 合作关系 | 对接方式、材料往来、待确认协作 | 不根据沉默推断内部政治或私人动机 |

无证据类别写本次未捕捉到。同一证据可支撑多个判断，但不可重复累计成多个独立需求。

## 优先级

先看客户已确认的期限、业务影响、发生频率和覆盖范围。可以高／中／低分组，逐条给证据，缺项写未知。客户已决定的事项单列，不能被主观评分覆盖。

正式模板若用急／频／疼／大四维评分，各 1–5 分，必须有相应证据；不具备评分依据时删除数字和比例条，用待确认代替，不能把未知填 0。评分仅为分析者判断，不能代表客户已批准的顺序。

## 追问与推进

- 事实：当前流程、样本、基线、使用范围和约束是什么？
- 预期：期望结果、验证方式、时间和可接受边界是什么？
- 决策与协作：谁参与评估、谁确认范围、后续流程如何安排？

优先给最影响下一步的问题，避免一次堆出完整问卷。成功指标、责任、报价和验收标准均需双方确认；未确认部分作为提议。

## 行动与备选

每项建议写动作、输入、负责人或待确认、时间或建议时间、完成标志。阶段可为需求澄清、方案评审、试点验证，按客户实际流程调整，不预设固定成交周数。

风险写来源、可能影响与需要核实的条件。备选安排写“若条件发生，则采取什么动作”。不制造虚假紧迫性、稀缺性或默认报价承诺，不把回复速度当成预算或签约意愿的证明。

## 正式报告章节

分析报告保留结论、背景、证据、痛点、认可、需求、方向、决策、竞争／协作与行动。推进报告保留追问、阶段安排、双方条件、风险与下一步。空缺项明确标注，按用户用途裁剪。
