# 客户拜访备课｜查客户、找切入点

整理客户怎么做生意、哪些变化与本次沟通有关、见面该问什么。基于公开信息和用户材料，给出事实、合作假设和下一步。

## 开始工作

识别目标公司、我方业务方向和接触阶段。目标无法唯一识别时先消歧；缺少业务方向时可先研究公司，合作建议标为待补充。阶段未知时按首次接触处理，说明假设。一次询问关键缺口，已有信息不重复问。

默认简版，通常一至两页。用户要求深研、投标或正式提案时，才扩展财务、竞争、技术和采购流程。不为凑资料数量扩大检索。

## 查证与分析

1. 优先查官网、投资者关系、交易所公告、帮助中心和官方采购信息。其他来源补充背景，见 [信源选择](references/行业信源地图.md)。
2. 按问题检索。数字保留年份、单位和披露口径；事件记录发布日期与发生日期。
3. 事实附近附来源链接。用户材料标注文件名或位置。检索不到写未查到，不等同于不存在。
4. 提出合作假设，列依据、我方能力和需要客户确认的问题。招聘、媒体热度和投诉只提供线索，不能证明预算、采购意愿或整体口碑。
5. 建议落到确认问题、请求材料、演示或试点条件。缺少我方能力证据时，不承诺功能、效果、报价、日期或案例。

联网不可用时，只分析用户材料，说明未进行最新公开信息核查。旧报告未刷新时不得标成最新。

## 默认交付

按材料多少裁剪，不机械填满各节。

- 客户画像：卖什么、卖给谁、收入来源和主要渠道。
- 关键变化：与本次沟通有关的事件和影响。
- 合作假设：客户问题／证据／我方可验证能力／待确认项。
- 拜访问题：确认目标、现状、约束和决策流程。
- 下一步：建议动作、所需输入和可观察的完成标志。

自用版保留内部假设。转发版用中性措辞，去掉未经核实的个人动机和内部评价，保留不确定性。末尾注明信息截止日、来源和覆盖缺口。

## 边界与衔接

不猜测联系人私生活、个人动机或内部权力关系。预算、合同期限、拍板人和采购节点未知时写待确认；公开职位不能单独证明决策权限。

默认在聊天交付。用户要存档或展示版时，再生成 Markdown 或自包含 HTML，遵循指定目录并保留旧版本。报告不自动发送给客户，也不自动启动监控。

配套技能可用时，可把事实和缺口交给 client-meeting-intel 或 client-deliverables；未安装时独立交付本次报告。

## 试用

- 准备拜访一家连锁零售企业。我方提供会员运营服务，帮我查客户并列五个关键问题。
- 根据这份年报整理业务、近期变化和合作假设，每条事实附来源。
- 把已有分析改成可发同事的拜访准备，保留待确认项。

教学示例：公告计划扩店，可提出“新增门店的会员运营一致性可能需要确认”。不能据此写成“客户已批准会员系统预算”。
