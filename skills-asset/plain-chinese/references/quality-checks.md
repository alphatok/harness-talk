# 信息保真与读者验收

用于复杂改写、含数字或条件的说明、操作手册和正式交付物。短回复选择相关检查项即可。默认内部检查，用户要求时才展示报告。

## 信息保真

以原文或已核实材料为基准，必要时建立下表。每项可以对应多个句子；允许调整顺序，不要求逐字对应。

| 原始信息或来源位置 | 不可改变的含义 | 输出对应位置 | 处理结果 |
|---|---|---|---|
| 原文片段或来源 | 对象、关系与限定 | 改写片段或段落 | 保留／摘要省略／待确认 |

“摘要省略”仅用于任务允许的摘要。记录重要省略及其影响；普通摘要无需逐项展示记录。纯改写只删除重复或无信息的文字。

### 逐项核对

| 项目 | 检查问题 |
|---|---|
| 对象和动作 | 谁做什么？对象是否混淆？谁承担义务？ |
| 数值与口径 | 数字、单位、分母、时间窗、比较基准和端点是否保留？相对日期是否被擅自具体化？ |
| 条件和例外 | 动作适用的前提、排除条件和例外是否完整？ |
| 逻辑关系 | 且／或、全部／部分、先后、因果／相关、必要／充分是否变化？ |
| 否定和义务 | 不得、必须、可以、建议是否变弱或变强？ |
| 确定性和程度 | 可能、通常、不太、至少、仅等限定是否保留？ |
| 证据和状态 | 观察、推断、建议、计划、已完成、未验证是否混用？ |
| 精确文本 | 命令、路径、报错、引文、公式等是否保持精确？ |
| 新增信息 | 输出有无无来源的原因、机制、角色、期限或测试结论？ |

遇到来源冲突，保留冲突和来源边界。无法判断时标为待确认，不选一个更顺口的说法。材料未提供的信息不能靠改写获得。

任一关键含义改变或新增事实缺少依据，先修正再交付。无法修正时局部保留原文并说明问题，不将有问题的改写标为通过。

## 读者能否使用

这四项检查借鉴 ISO 24495-1 的读者结果原则。以下问题和验收做法是本技能的实践方法，不是 ISO 认证流程。

| 原则 | 检查问题 |
|---|---|
| 满足需要 | 是否回答本次读者的问题？关键内容是否被删掉？是否夹杂与用途无关的材料？ |
| 容易找到 | 结论、条件、操作或决定放在哪里？能否快速定位？ |
| 容易理解 | 读者是否认识术语？主语、指代、因果和范围是否明确？ |
| 能够使用 | 读者能否完成本次目的？是否缺少必要条件或完成标准？ |

按任务选择验收问题，不要求每篇文字包含所有字段：

- 解释：能否复述主要结论、原因和适用边界？
- 操作说明：能否判断何时执行、执行什么、需要什么输入、怎样算完成，以及遇到已知异常时如何处理？
- 进展汇报：能否区分已完成、未验证、风险及待决策事项？有分工安排时，能否找到负责人和期限？
- 决策材料：能否区分事实、假设、选项、代价和待确认项，并识别当前要作的决定？

## 两层验证

### 模型自检

从正文逐项定位上述问题的答案。材料不足时列出必要缺口。自行模拟读者、由另一模型评审或脚本扫描，都只算辅助检查。

可报告“已完成保真核对与模型自检”。不得报告“读者一次看懂”“用户可以正确执行”或“已通过真实读者验收”。

### 真实读者验收

仅在实际安排了目标读者参与时执行。技能不自动联系他人或发送内容。

1. 记录读者角色、材料版本、任务和预先确定的通过条件。按用途设置要求，不统一规定时长或分数。
2. 让读者独立阅读，再复述要点或执行任务。避免先解释预期答案。
3. 记录实际结果、错误、额外追问与协助。区分正文提供的信息和口头补充。
4. 按预定条件判断本次结果。修订后必要时复验；一次通过不代表对所有读者有效。

没有目标读者参与时写“真实读者验收未进行”。不能把缺少验收解释为失败，也不能将自检升级为通过。

## 报告方式

只在用户要求或验证结论影响交付时展示。

| 检查项 | 证据或发现 | 结论 |
|---|---|---|
| 信息保真 | 原文与输出的对应位置、已修正的问题 | 已核对／存在待确认 |
| 读者使用检查 | 正文中的答案或必要缺口 | 已自检／待补信息 |
| 真实读者验收 | 实际任务记录；没有则注明 | 本次通过／本次未通过／未进行 |

不要用自动词数检查替代语义核对，也不要用模型评分替代真实读者结果。
