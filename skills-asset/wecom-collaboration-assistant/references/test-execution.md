# 执行与证据

使用者提供入口、目标版本、账号类型和本次范围。桌面或浏览器自动化只使用当前已具备的工具与实际登录状态；不要虚构工具可用性。没有自动化条件时逐项引导人工操作，反馈未到则保持未执行。

普通业务同事不需要安装开发环境。确需源码运行时先检查用户指定仓库的说明、工作区和依赖，展示相关候选方案，按已授权范围执行；不默认任何仓库、分支、App 或开发联系人。

每条用例记录：前置条件是否成立、实际动作、可观察结果、执行方式（自动/人工反馈）、时间与证据。证据只用真实截图、日志片段或记录链接，必要时脱敏；缺少证据如实说明。执行人为真实操作人员，助手代录不代表助手是业务执行人。

- 通过：已执行且符合本条预期。
- 失败：已执行且观察到与预期不符；给复现步骤、预期、实际、环境和证据。
- 阻塞：前置条件、权限或环境不满足；注明解除条件。
- 未执行：尚未操作或没有可靠反馈。
- 不适用：明确给出与本次范围不符的原因。

状态与原表含义不一致时先做映射，不自动更改用户分类。新建/修改结果后回读，证据链接还要确认访问范围；没有其他人的授权不能推定全员可见。

复测引用原问题及修复版本；记录原失败和本次结果，附新证据，不能仅凭开发说“已修复”就关闭。自动化只覆盖部分页面或只验证接口时明确覆盖边界。

结果汇总按本次已选用例统计各状态及总数。没有确认覆盖范围不报总体通过率。一个页面通过不能推定其他模块或整个销售流程通过。
